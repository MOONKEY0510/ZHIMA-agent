# Agent 助手功能演进计划

## 一、目标

围绕“轻量、可控、易理解、适合桌面工作”的定位，继续完善当前 Agent 能力：

1. 让工具权限更细致；
2. 让 Agent 执行过程更透明；
3. 让长任务更可靠；
4. 增强剪贴板、文件和桌面工作流；
5. 保持应用轻量，避免过早引入复杂扩展体系。

---

## 二、当前基础

当前项目已经具备：

- 多 Provider、多模型支持；
- 流式聊天；
- Agent 多轮工具调用；
- 工具风险等级和人工确认；
- 联网搜索、网页读取；
- 剪贴板、文件、PDF、截图等桌面工具；
- 对话历史和 SQLite 存储；
- 长对话摘要与上下文控制；
- Agent 工具总开关；
- 设置页 Agent 工具列表；
- 请求取消、重试和错误处理。

当前主要缺口：

- 工具只能整体启用或关闭；
- 工具审批粒度较粗；
- Agent 执行过程不够直观；
- 工具结果和上下文预算管理不足；
- 缺少高频桌面工作流；
- 长任务无法暂停和恢复。

# 三、第一阶段：工具权限与审批体系

预计工期：3～5 天。

## 1. 工具单独启用和禁用

在设置页的 Agent 工具列表中，为每个工具增加策略选择：

- 默认允许；
- 每次确认；
- 默认禁用；
- 仅本次会话启用。

建议默认策略：

| 工具 | 默认策略 |
|---|---|
| 获取当前时间 | 默认允许 |
| 计算 | 默认允许 |
| 联网搜索 | 默认允许或每次确认 |
| 抓取网页 | 每次确认 |
| 读取剪贴板 | 每次确认 |
| 写入剪贴板 | 每次确认 |
| 读取文本文件 | 每次确认 |
| 读取 PDF | 每次确认 |
| 截屏 | 每次确认 |
| 打开资源 | 每次确认 |

涉及模块：

- `src-tauri/src/storage/config.rs`
- `src-tauri/src/tools/registry.rs`
- `src-tauri/src/commands/chat.rs`
- `src/features/settings/SettingsPanel.tsx`

验收标准：

- 设置页可以单独修改每个工具的策略；
- 修改后重启应用仍然保留；
- 被禁用的工具不会发送给模型；
- 工具策略不会影响其他 Provider 配置。

## 2. 完善工具审批弹窗

将现有简单审批升级为详细审批卡片，显示：

- 工具名称；
- 操作说明；
- 访问的数据类型；
- 是否联网；
- 参数摘要；
- 风险等级；
- 允许范围。

按钮包括：

- 拒绝；
- 仅允许这一次；
- 本次会话允许；
- 永久允许。

示例：

```text
Agent 请求读取剪贴板

操作：
读取当前剪贴板中的文本内容，并提供给模型分析。

数据访问：
本地剪贴板

[拒绝] [仅允许一次] [本次会话允许]
```

验收标准：

- 用户可以明确知道 Agent 要执行什么；
- 不同允许范围会产生不同结果；
- 敏感工具默认不会静默执行；
- 审批超时后自动拒绝。

## 3. 增加会话级工具策略

聊天输入框的工具设置增加临时策略：

- 本次对话继承全局设置；
- 本次对话全部关闭；
- 本次对话全部开启；
- 查看当前允许的工具。

会话级设置不覆盖全局设置，只对当前会话生效。

# 四、第二阶段：Agent 任务计划和过程展示

预计工期：3～5 天。

## 4. 增加任务进度视图

长任务开始后显示：

```text
正在处理：整理下载目录中的 PDF

✓ 找到文件
✓ 读取 PDF 内容
● 提取关键信息
○ 生成汇总
```

每个步骤包括：

- 步骤名称；
- 当前状态；
- 开始时间；
- 完成时间；
- 执行耗时；
- 错误信息。

后端为工具调用增加：

- `step_id`
- `parent_step_id`
- `title`
- `status`
- `started_at`
- `finished_at`

前端显示位置：

- 聊天消息中的工具详情栏；
- 长任务期间的顶部状态条；
- Agent 结果消息中的执行摘要。

## 5. 工具调用结果可展开查看

默认只显示摘要：

```text
联网搜索完成，找到 8 条结果
读取 PDF 完成，共 24 页
```

点击后展开：

- 工具参数；
- 工具原始结果；
- 截断提示；
- 执行时间；
- 错误信息。

这样可以减少聊天界面干扰，同时保留调试能力。

## 6. 支持失败步骤重试

当某个工具执行失败时，提供：

- 重试当前步骤；
- 跳过当前步骤；
- 不使用工具继续；
- 返回上一步重新规划。

例如网页读取失败时，可以自动尝试：

1. 重试当前地址；
2. 改用搜索结果摘要；
3. 请求用户提供网页内容；
4. 继续生成部分答案。

# 五、第三阶段：上下文和结果管理

预计工期：2～4 天。

## 7. 建立 Agent 上下文预算

统一管理：

- 工具定义占用；
- 工具调用参数；
- 工具结果；
- 搜索结果；
- 网页正文；
- 文件内容；
- 历史消息；
- 摘要内容。

建议设置：

- 单个工具结果上限；
- 单轮工具结果总上限；
- 整个 Agent 任务工具结果总上限；
- 预留模型输出空间。

超过预算时：

1. 优先保留结论和关键字段；
2. 删除重复搜索结果；
3. 压缩网页内容；
4. 对长文本执行摘要；
5. 向用户提示内容已压缩。

## 8. 优化搜索和网页结果

联网搜索结果只保留：

- 标题；
- URL；
- 摘要；
- 来源；
- 发布时间。

网页读取增加正文提取：

- 移除导航；
- 移除广告；
- 移除脚本和样式；
- 提取正文标题和段落；
- 保留必要链接。

## 9. 工具结果摘要

工具执行后同时保存：

- `raw_result`：完整结果，仅用于需要时查看；
- `summary`：发送给模型的精简结果；
- `metadata`：耗时、大小、来源、是否截断。

聊天界面默认显示摘要，避免大段工具结果挤占对话内容。

# 六、第四阶段：桌面生产力工作流

预计工期：5～8 天。

## 10. 剪贴板工作流

增加快捷操作：

- 总结剪贴板；
- 翻译剪贴板；
- 改写剪贴板；
- 提取待办；
- 格式化 JSON；
- 格式化 SQL；
- 清理文本格式；
- 结果写回剪贴板。

使用流程：

1. 用户复制文本；
2. 打开 ChatFloat 快捷入口；
3. 选择一个操作；
4. Agent 处理文本；
5. 用户确认后复制结果。

## 11. 文件批处理工作流

支持用户选择多个文件或目录：

- 批量重命名；
- 批量提取 PDF 标题；
- 合并 Markdown；
- 批量生成摘要；
- 文件分类；
- 批量翻译；
- 生成目录索引。

必须提供：

- 操作预览；
- 受影响文件列表；
- 执行前确认；
- 自动备份；
- 失败文件列表；
- 撤销或恢复入口。

禁止默认直接覆盖原始文件。

## 12. 文档处理工作流

增加预设任务：

- PDF 总结；
- 多文档对比；
- 提取表格；
- 提取关键日期；
- 生成会议纪要；
- 生成报告大纲；
- 文档问答。

# 七、第五阶段：记忆和对话管理

预计工期：3～5 天。

## 13. 改进长期记忆

记忆增加：

- 来源消息；
- 创建时间；
- 最近使用时间；
- 重要性；
- 过期时间；
- 用户确认状态。

记忆分类：

- 用户偏好；
- 工作背景；
- 项目信息；
- 临时任务；
- 明确要求长期保存的信息。

## 14. 记忆确认机制

Agent 不应默认保存所有内容。建议：

```text
我发现这可能是你的长期偏好：
“你喜欢使用简洁的回答格式”

是否保存？

[不保存] [仅本次使用] [保存为长期偏好]
```

设置页提供：

- 查看记忆；
- 编辑记忆；
- 删除记忆；
- 清空全部记忆；
- 暂停自动记忆。

## 15. 对话分支和回溯

支持：

- 从任意消息创建分支；
- 重新生成；
- 不使用工具重试；
- 更换模型继续；
- 更换系统提示词继续；
- 对比不同答案。

展示结构：

```text
主对话
├── 分支 A：启用联网
├── 分支 B：关闭工具
└── 分支 C：使用快速模型
```

# 八、第六阶段：长任务和运行记录

预计工期：4～6 天。

## 16. 长任务暂停与恢复

支持：

- 暂停；
- 继续；
- 取消；
- 重试当前步骤；
- 从失败步骤继续；

保存内容：

- 任务 ID；
- 当前步骤；
- 工具调用参数；
- 工具结果；
- 当前任务状态；
- 失败原因；
- 最后更新时间。

## 17. Agent 运行记录

新增运行记录页面，展示：

- 任务耗时；
- 模型调用次数；
- 工具调用次数；
- 各工具耗时；
- 输入 Token；
- 输出 Token；
- 重试次数；
- 失败原因；
- 估算费用。

用途：

- 查找 Agent 变慢原因；
- 查看工具是否频繁失败；
- 对比不同模型效果；
- 排查异常消耗。
